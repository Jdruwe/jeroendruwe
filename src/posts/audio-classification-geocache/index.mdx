I built a geocache that asks people to imitate a chicken. Cachers scan a QR code, get redirected to [toktoktok.pages.dev](https://toktoktok.pages.dev/), and make chicken sounds into their phone. The browser uses Google's MediaPipe to classify the audio in real-time. If the attempt is convincing enough, they get the combination to unlock the container.

This post covers how I built it, from capturing audio with the Web Audio API to running machine learning models in the browser.

## Geocache

If you're not familiar with geocaching, it's an outdoor treasure hunt using GPS coordinates. Someone hides a container, posts the coordinates online at [geocaching.com](https://www.geocaching.com/), and others use their phones or GPS devices to find it. There are over 3 million active geocaches worldwide.

Most are straightforward: find the container, sign the logbook, move on. But puzzle caches require solving challenges before you can access the container. These usually involve riddles, ciphers, or math problems solved at home before heading outside.

## Capturing Audio

The first step in building the audio classification system was getting access to the user's microphone. This is handled by the [Media Capture and Streams API](https://developer.mozilla.org/en-US/docs/Web/API/Media_Capture_and_Streams_API), which provides a standardized way to access media input devices in the browser.

The core of this API is [`getUserMedia()`](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia), a method that prompts the user for permission to access their microphone or camera. When you call it with `{ audio: true }`, the browser shows a permission dialog. If the user approves, you get a [`MediaStream`](https://developer.mozilla.org/en-US/docs/Web/API/MediaStream) object containing the audio track from their microphone.

```tsx
const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
```

The `MediaStream` represents a stream of media content, in this case audio data from the microphone. This stream can be used in multiple ways—recording it with MediaRecorder, processing it with the Web Audio API, or even streaming it to another user in a WebRTC call.

## Recording Audio

Once I had access to the microphone via `getUserMedia()`, I needed a way to actually record and store the audio. [MediaStream Recording API](https://developer.mozilla.org/en-US/docs/Web/API/MediaStream_Recording_API) to the rescue.

The [`MediaRecorder`](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder) interface takes a `MediaStream` and records it into chunks of data. You attach event handlers to collect these chunks, and when recording stops, you combine them into a single audio file (typically a Blob) that can be played back or sent to a server.

Here's how MediaRecorder works in practice:

1. Get a MediaStream from `getUserMedia({ audio: true })`
2. Create a MediaRecorder instance with that stream
3. Attach event handlers for `ondataavailable` and `onstop`
4. Call `recorder.start()` to begin capturing
5. Collect chunks in `ondataavailable`
6. Call `recorder.stop()` when the user is done
7. In `onstop`, combine chunks into a Blob and create an object URL

Here's a basic recording demo to see it in action:

</NoProse>

```tsx
// use-audio-recorder.ts
const audioChunksRef = useRef<Blob[]>([]);

const createMediaRecorder = (stream: MediaStream) => {
  const recorder = new MediaRecorder(stream);

  recorder.ondataavailable = (e) => {
    if (e.data.size > 0) audioChunksRef.current.push(e.data);
  };

  recorder.onstop = () => {
    const blob = new Blob(audioChunksRef.current, { type: 'audio/webm' });
    const url = URL.createObjectURL(blob);
    setAudioUrl(url);
    stopStreamTracks(stream);
    mediaStreamRef.current = null;
  };

  return recorder;
};

const startRecording = async () => {
  try {
    const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
    const recorder = createMediaRecorder(stream);
    recorder.start();
    setIsRecording(true);
  } catch (err) {
    setError('Failed to start recording. Please try again.');
    setIsRecording(false);
  }
};
```

Recording audio with MediaRecorder works fine for playback, but for real-time audio classification, I needed something more powerful. That's where the [Web Audio API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API) comes in.

The Web Audio API is designed for processing and synthesizing audio in the browser. Unlike MediaRecorder, which simply records chunks of audio, the Web Audio API gives you fine-grained control over audio streams through a modular system of **audio nodes**.

### Audio Nodes and the Audio Graph

The core concept of the Web Audio API is the **audio graph**—a network of audio nodes connected together. Each node performs a specific function, like capturing input, applying effects, analyzing frequency data, or outputting to speakers.

Here's how nodes connect:

1. **Source nodes** - Generate or capture audio (like a microphone stream)
2. **Processing nodes** - Modify or analyze the audio (like gain control, filters, or custom processing)
3. **Destination nodes** - Output the audio (usually to speakers, but can also be to another stream)

Nodes are connected using the `.connect()` method, creating a chain through which audio flows:

## Audio Classification

For my use case, I needed an audio classification solution that could run entirely client-side. The goal was to have something that works on a mobile device without relying on a server. This requirement ruled out all cloud-based ML APIs and pushed me toward on-device machine learning.

### MediaPipe Studio

[MediaPipe Studio](https://mediapipe-studio.webapps.google.com/home) is a web-based tool for testing and customizing on-device machine learning models. For audio-based projects, the [Audio Classifier](https://mediapipe-studio.webapps.google.com/studio/demo/audio_classifier) allows you to perform real-time sound recognition directly in the browser.

#### Technical Details

* **Model:** It leverages **[YAMNet](https://www.kaggle.com/models/google/yamnet)**, a deep neural network capable of predicting 521 different audio event classes based on the AudioSet dataset.
* **Configuration:** You can adjust inference settings such as **Score threshold** (to filter out low-confidence predictions) and **Max results** (to limit the number of detected categories).
* **Supported SDKs:** MediaPipe provides native libraries across several environments: **Web:** JavaScript / TypeScript (see this [official CodePen example](https://codepen.io/mediapipe-preview/pen/wvxYYmy)), **Android:** Java / Kotlin & **Python**.
