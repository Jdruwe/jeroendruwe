## The Cloudflare Stack

I'm building Gieter entirely on Cloudflare's platform. For a personal project like mine, their free tier is [unmatched](https://developers.cloudflare.com/workers/platform/pricing/).

The plant importer is just the first piece. As Gieter grows, I'll use:

- **D1** for storing plants, tasks, and user data
- **R2** for plant images
- **Workers** for the frontend
- **Workers AI** for potential future features like plant identification from photos

### ImportPlantWorkflow

Cloudflare Workflows provide durable execution for multi-step processes. Each step wrapped in `step.do()` is persisted, so if a later step fails, completed steps don't re-run. This is perfect for the plant importer, where each step (search, extract, generate) can take time and may need retries.

#### Step 1: Search with Tavily

I use [Tavily](https://tavily.com/) for web search. Using their [Javascript SDK](https://docs.tavily.com/sdk/javascript/reference) I look for for relevant results. Initially I was planning on scraping the web myself using Playwright and Google but I bumped into Google’s scraping protection fast. Tavily has all of this figured out and you can start for free.

```typescript
const tavilyClient = tavily({ apiKey: process.env['TAVILY_API_KEY'] });

const searchResponse = await step.do('search', async () => {
  return await tavilyClient.search(
    `${event.payload.plant} onderhoudskalender België`,
    { country: 'Belgium' },
  );
});
```

I search in Dutch to find locally relevant results, with the `country: 'Belgium'` parameter further narrowing to Belgian sources:

```
${plant} onderhoudskalender België
```

This returns a list of URLs with plant care information. Wrapping the call in `step.do()` ensures the search results are persisted.

#### Step 2: Extract Content

Tavily's extract API scrapes the URLs from step 1, returning clean markdown by default. This gives me structured text from gardening websites, forums, and care guides, ideal source material for the AI to generate a maintenance plan.

```typescript
const extractResponse = await step.do('extract content', async () => {
  return await tavilyClient.extract(searchResponse.results.map((r) => r.url));
});
```

#### Step 3: Generate Structured Output

This is where the magic happens. I use the Vercel AI SDK with OpenAI to generate a structured maintenance plan. The key is using Zod schemas to ensure the output is exactly what I need. For now I am extracting the plant name, type, sources used, and a list of tasks with descriptions, deadlines, and required products.

```typescript
return await step.do('generate plan', async () => {
  const { output } = await generateText({
    model: openai('gpt-5-mini-2025-08-07'),
    output: Output.object({
      schema: z.object({
        name: z.string().describe('Name of the plant'),
        type: z.string().describe('Type of plant, e.g. flowers, tree, etc.'),
        sources: z.array(z.string()).describe('List of relevant links used'),
        tasks: z.array(
          z.object({
            description: z
              .string()
              .describe('Description of the maintenance task'),
            deadline: z.object({
              month: z.number().describe('Numeric month, e.g. 1 for January'),
              day: z.number().describe('Numeric day of the month'),
            }),
            products: z
              .array(z.string())
              .describe('Products needed, e.g. fertilizers, tools'),
          }),
        ),
      }),
    }),
    // ... prompt configuration, see below for more details
  });

  return output;
});
```

##### System prompt

Implementing a robust system prompt is essential for ensuring the model generates high-quality, consistent maintenance plans.

```typescript
system: `
	- Only use the <extraction-results> as a source of truth, do NOT generate something of your own
	- Generate output in Dutch, even if the input is in another language.
	- Avoid using vague references like 'in three months' or 'late autumn.' Always calculate and state the exact deadline or scheduled date for a task to ensure maintenance logs remain actionable and unambiguous.
	- Sort maintenance tasks by date ascending
	- Providing enough details when pruning info is shared`;
```

##### Prompt

I am using [Anthropic's prompt template](https://www.youtube.com/watch?v=ysPbXH0LpIE) which I encountered when following the AI SDK Crash Course from Matt Pocock.

```typescript
prompt: `
<task-context>
	You are a helpful plant assistant that creates a maintenance plan requested by the user.
</task-context>

<background-data>
	<extraction-results>
		${extractResponse.results
      .map(
        (result) => `
				<result>
					<title>${result.title}</title>
					<url>${result.url}</url>
					<content>${result.rawContent}</content>
				</result>
			`,
      )
      .join('\n')}
	</extraction-results>
</background-data>

<the-ask>
	The user request a plan to be made for: <plant>${event.payload.plant}</plant>
</the-ask>`;
```

#### Triggering the Workflow

For now, the workflow is exposed through a simple fetch handler:

```typescript
export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);

    // Check status of existing workflow
    const instanceId = url.searchParams.get('instanceId');
    if (instanceId) {
      const instance = await env.IMPORT_PLANT_WORKFLOW.get(instanceId);
      return Response.json(await instance.status());
    }

    // Start new workflow
    const plant = url.searchParams.get('plant');
    if (!plant) {
      return new Response("Missing 'plant' parameter", { status: 400 });
    }

    const instance = await env.IMPORT_PLANT_WORKFLOW.create({
      params: { plant },
    });

    return Response.json({ instanceId: instance.id });
  },
} satisfies ExportedHandler<Env>;
```

**Starting an import**

```bash
curl "http://localhost:8787/?plant=Hortensia"
# Response: { "instanceId": "73279953-cbef-4bec-85bd-97690fc6940f" }
```

**Checking workflow status**

```bash
curl "http://localhost:8787/?instanceId=73279953-cbef-4bec-85bd-97690fc6940f"
```
