## The Cloudflare Stack

I'm building Gieter entirely on Cloudflare's platform. For a personal side project, their free tier is [unmatched](https://developers.cloudflare.com/workers/platform/pricing/).

The plant importer is just the first piece. As Gieter grows, I'll use:

- **D1** for storing plants, tasks, and user data
- **R2** for plant images
- **Workers** for the frontend
- **Workers AI** for potential future features like plant identification from photos

### Workflows

> With Workflows, you can build applications that chain together multiple steps, automatically retry failed tasks, and persist state for minutes, hours, or even weeks - with no infrastructure to manage.

The plant importer does three things:

1. **Search** - Find relevant care information for the plant
2. **Extract** - Scrape content from the search results
3. **Generate** - Use AI to create a structured maintenance plan

Here's the full workflow class, which I'll break down step by step:

### Step 1: Search with Tavily

I use [Tavily](https://tavily.com/) for web search. Using their [Javascript SDK](https://docs.tavily.com/sdk/javascript/reference) I look for for relevant results. Initially I was planning on scraping the web myself using Playwright and Google but I bumped into Google’s scraping protection fast. Tavily has all of this figured out and you can start for free.

```typescript
const tavilyClient = tavily({ apiKey: process.env['TAVILY_API_KEY'] });

const searchResponse = await step.do('search', async () => {
  return await tavilyClient.search(
    `${event.payload.plant} onderhoudskalender België`,
    { country: 'Belgium' },
  );
});
```

I search in Dutch since I want Belgium-specific care information:

```
${plant} onderhoudskalender België
```

This returns a list of URLs with plant care information. Wrapping the call in `step.do()` ensures the search results are persisted - if a later step fails, this step won't re-run.

### Step 2: Extract Content

```typescript
const extractResponse = await step.do('extract content', async () => {
  return await tavilyClient.extract(searchResponse.results.map((r) => r.url));
});
```

Tavily's extract API scrapes the raw content from the URLs found in step 1. This gives me the actual text from gardening websites, forums, and care guides - the source material the AI will use to generate the maintenance plan.

### Step 3: Generate Structured Output

```typescript
return await step.do('generate plan', async () => {
  const { output } = await generateText({
    model: openai('gpt-5-mini-2025-08-07'),
    output: Output.object({
      schema: z.object({
        name: z.string().describe('Name of the plant'),
        type: z.string().describe('Type of plant, e.g. flowers, tree, etc.'),
        sources: z.array(z.string()).describe('List of relevant links used'),
        tasks: z.array(
          z.object({
            description: z
              .string()
              .describe('Description of the maintenance task'),
            deadline: z.object({
              month: z.number().describe('Numeric month, e.g. 1 for January'),
              day: z.number().describe('Numeric day of the month'),
            }),
            products: z
              .array(z.string())
              .describe('Products needed, e.g. fertilizers, tools'),
          }),
        ),
      }),
    }),
    // ... prompt configuration
  });

  return output;
});
```

This is where the magic happens. I use the Vercel AI SDK with OpenAI to generate a structured maintenance plan. The key is using Zod schemas to ensure the output is exactly what I need - plant name, type, sources used, and a list of tasks with descriptions, deadlines, and required products.

The AI is instructed to:

- Only use the extracted content (no hallucinating care advice)
- Output in Dutch
- Provide exact dates (no "in late autumn")
- Sort tasks by date

## Triggering the Workflow

The workflow is exposed through a simple fetch handler:

```typescript
export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);

    // Check status of existing workflow
    const instanceId = url.searchParams.get('instanceId');
    if (instanceId) {
      const instance = await env.IMPORT_PLANT_WORKFLOW.get(instanceId);
      return Response.json(await instance.status());
    }

    // Start new workflow
    const plant = url.searchParams.get('plant');
    if (!plant) {
      return new Response("Missing 'plant' parameter", { status: 400 });
    }

    const instance = await env.IMPORT_PLANT_WORKFLOW.create({
      params: { plant },
    });

    return Response.json({ instanceId: instance.id });
  },
} satisfies ExportedHandler<Env>;
```

To start an import:

```bash
curl "http://localhost:8787/?plant=Hortensia"
# Response: { "instanceId": "73279953-cbef-4bec-85bd-97690fc6940f" }
```

To check progress:

```bash
curl "http://localhost:8787/?instanceId=73279953-cbef-4bec-85bd-97690fc6940f"
```
